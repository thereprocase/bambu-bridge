Getting started

Bambu Bridge · Manual · Getting started

Install the bridge once on a small always-on Linux box, pair the Android app with it, add the printer. After that the app is the daily remote and the web app is there for a laptop.

What you need

  • A Linux host for the bridge (a mini PC, a NAS, a Raspberry Pi, or a Home Assistant OS box).
  • A Bambu Lab P1S on the same network, with LAN-Only Mode on. The bridge talks to the printer directly; it never uses Bambu's cloud.
  • A Spoolman server if you want spool tracking. Spoolman is the only place spools live; the bridge reads and charges them there.
  • Optional: Tailscale on the bridge host and your phone, so the app works away from home.

1. Install the bridge

  1. On the bridge host, from a checkout of the project: 
    python3.12 -m venv ~/bambu-bridge/.venv
~/bambu-bridge/.venv/bin/pip install .
bash deploy/install.sh
    The installer sets up a per-user systemd unit, generates an API key and writes it to ~/.config/bambu-bridge/bridge.env.
  2. Read the key once; you paste it into the app in step 3: 
    grep '^BRIDGE_API_KEY=' ~/.config/bambu-bridge/bridge.env
  3. For spool tracking, add the Spoolman address to the same file and restart the service: 
    BRIDGE_SPOOLMAN_URL=http://<spoolman-host>:7912
systemctl --user restart bambu-bridge

The bridge listens on port 8080. Home Assistant OS and the full runbook: GETTING-STARTED and deploy/DEPLOY.md in the repository.

2. Prepare the printer

  1. On the printer's touchscreen, turn on LAN-Only Mode in the network settings. If the firmware offers Developer Mode, turn it on too.
  2. Note the printer's IP address and its 8-digit access code (Settings ▸ WLAN ▸ Access Code).
  3. Give the printer a fixed address in your router (a DHCP reservation). If its address changes later, the bridge loses it until you update the printer's address in Settings.

3. Set up the app

  1. Install the APK the owner's build pipeline produced for your phone (the app is distributed as a signed APK; there is no store listing).
  2. Open it. On first launch it lands on Settings · Connect your bridge.
  3. Tap Manual setup / compatibility, enter the bridge's address ending in /api/v1 (for example http://<bridge-host>:8080/api/v1) and paste the API key, then tap Save & probe. "Reachable" under the address means the key works. A LAN address can be added underneath; the app uses it first when you're on a saved home network and falls back to the remote one.
  4. Pair with QR code is the other way in: the bridge's web app shows a one-time pairing code that the app scans; it expires, so scan it when it's shown.
  5. Tap Add a printer, enter Host (IP) and Access code (a friendly name is optional) and tap Probe & connect. The bridge checks the connection and reads the serial from the printer itself; you never type a serial. "Connected to <name>" means it worked. The three failures the bridge names: wrong IP or printer off; wrong code or LAN-Only Mode off; connected but the printer went quiet.
  6. Tap Open dashboard. The Status tab is home.
The bridge refuses every request until it has an API key, and a wrong key is never saved by the app.

4. First look

The app has six tabs: Status (camera, progress, temperatures, quick actions), Print (files on the printer, start one), Controls, Filament (every AMS slot and the external holder, with their Spoolman spools), Activity (what happened), Advanced (raw printer commands, for when you know what you're doing). The gear opens Settings; the list icon opens the bridge's print queue.
